# متجر تطبيقات خاص (IPA + كود اشتراك)

نظام بسيط لتوزيع تطبيقات iOS من تطويرك الخاص، موقّعة بشهادة **Apple Developer Enterprise واحدة**، عبر أكواد اشتراك صالحة لمدة سنة.

## المتطلبات قبل التشغيل

1. **حساب Apple Developer Enterprise** ($299/سنة) — من https://developer.apple.com/programs/enterprise/
   منه بتصدّر ملفين: شهادة التوزيع كـ **`.p12`** (مع كلمة سر)، وملف **`.mobileprovision`**
2. **زي `zsign` مثبّت على السيرفر** — التوقيع صار يصير تلقائياً جوا الموقع بدل ما تعمله يدوياً بـ Xcode:
   ```bash
   git clone https://github.com/zhlynn/zsign.git
   cd zsign/build/linux && ./build.sh   # يحتاج openssl-dev + cmake
   sudo cp zsign /usr/local/bin/
   ```
   (Xcode/`codesign` الرسمي من آبل يشتغل بس على macOS — `zsign` بديل مفتوح المصدر يعمل نفس الوظيفة على Linux ويُستخدم بشكل شائع لخطوط توزيع enterprise آلية)
3. **دومين حقيقي بشهادة HTTPS صالحة** — `itms-services://` ما بيشتغل على `http://` ولا على IP بدون شهادة SSL صحيحة

## التثبيت

```bash
npm install
ADMIN_TOKEN="ضع-توكن-قوي-هنا" BASE_URL="https://yourdomain.com" PORT=3000 npm start
```

- `ADMIN_TOKEN`: كلمة سر لوحة التحكم — غيّرها لأي شي عشوائي طويل
- `BASE_URL`: الدومين الحقيقي اللي رح يستضيف الموقع (لازم HTTPS)

## الاستخدام

1. افتح `https://yourdomain.com/admin.html`، حط الـ Admin Token
2. **مرة وحدة فقط:** ارفع ملف `.p12` + كلمة سره + ملف `.mobileprovision` بقسم "الشهادة" — هاي هي الشهادة الوحيدة يلي رح توقّع فيها كل التطبيقات
3. أضف التطبيق برفع الـ **IPA غير الموقّع** — السيرفر بيوقعه تلقائياً بـ zsign ويخزن النسخة الموقّعة
4. ولّد كود واربطه بالتطبيق
5. أعطِ الزبون الرابط `https://yourdomain.com/download.html`
6. الزبون يدخل الكود → يفعّل (أول استخدام = بداية سنة الصلاحية) → يضغط "تثبيت على الآيفون"

## كيف يشتغل تقنياً

- الكود يتفعّل أول مرة يُستخدم فيها فقط، وتنعد سنة كاملة من هاللحظة
- كل طلب تنزيل (manifest أو IPA نفسه) يتحقق من صلاحية الكود من جديد في قاعدة البيانات
- ملف الـ manifest.plist يتولّد ديناميكياً لكل كود، ويشاور على رابط IPA مرتبط بنفس الكود فقط

## أمان يستاهل تنتبهله قبل الإنتاج

- بدّل `ADMIN_TOKEN` الافتراضي فوراً
- حط الموقع خلف HTTPS حقيقي (Let's Encrypt مثلاً)
- فكّر بإضافة rate-limiting على `/api/verify-code` عشان حد ما يجرب أكواد عشوائية بسرعة
- SQLite كافي للبداية؛ لو الحجم كبر انقل لـ Postgres/MySQL
- كلمة سر الـ `.p12` تنخزن حالياً كنص عادي بقاعدة البيانات — لو رح تشغّل هذا بالإنتاج فعلياً، شفّرها (مثلاً بـ `crypto` مع مفتاح بمتغير بيئة) قبل التخزين
- الشهادات ما تنعرض على الموقع أبداً: السيرفر يفتح بس صفحتين (`admin.html` و `download.html`) وباقي الملفات خاصة

## هيكلة المشروع (كل الملفات بمجلد واحد بدون مجلدات داخلية)

```
server.js        # كل الـ routes
db.js            # قاعدة بيانات SQLite
admin.html       # لوحة التحكم
download.html    # صفحة الزبون
package.json
Dockerfile
railway.toml
.gitignore
```

البيانات (قاعدة البيانات + الـ IPA الموقّعة + الشهادات) تنحفظ تلقائياً بمجلد `data` يتسوّى وقت التشغيل.
على Railway: أضف Volume واحد واربطه بالمسار `/data` (المتغير `DATA_DIR=/data` جاهز داخل الـ Dockerfile).
